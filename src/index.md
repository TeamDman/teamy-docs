# Teamy Docs

Use [Find a solution](problem-index.md) to look up the problem you want to solve. This book explains how we have solved problems in our tools, why we chose those approaches and where to inspect the code. You should not need to know a project's name to discover its useful work.

The first two areas are [writing programs](writing-programs.md) and [playing games](playing-games.md). Both benefit from explicit goals and feedback, but their rewards and acceptable experiments can differ. The [glossary](glossary.md) gives shared terms without forcing every activity into the same model.

For new Teamy CLI projects, use Rust and [teamy-rust-cli](rust-cli-template.md). Learn the template's command routing, [logging](logging.md), [typed output](output-shape.md) and [cancellation](cancellation.md) before extending it. The book records both working capabilities and observed gaps, with links to their implementations.

The software topics are [command-line tools](good-cli.md), [desktop applications](desktop-applications.md), [machine learning and audio](machine-learning.md), and [source and file organization](source-and-files.md). Their implementation references connect each purpose to our prior art. [Curation](curating-prior-art.md) also brings in selected external references, including candidates found in public GitHub stars.

A documented expectation does not mean every existing tool already meets it. Public source snapshots, branch work and local prototypes are identified where their status matters.

This book contains unclassified guidance and synthetic examples approved for a public audience. [Publication and audiences](publication.md) describes that boundary and the GitHub Pages publishing workflow.

Start with the [CLI definition](glossary.md#cli) when the command-line vocabulary is unfamiliar.
