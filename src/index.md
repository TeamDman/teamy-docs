# Teamy Docs

This book collects practical strategies that can be applied across projects. Start with a concrete objective, state the constraints, and make the next action easy to review.

The first two areas are [writing programs](writing-programs.md) and [playing games](playing-games.md). Both benefit from explicit goals and feedback, but their rewards and acceptable experiments can differ. The [glossary](glossary.md) gives shared terms without forcing every activity into the same model.

For software work, use the [CLI conventions](good-cli.md), [source lookup](source-lookup.md), [Windows path guidance](windows-paths.md), and [repository hygiene](repository-hygiene.md) as starting points. These are recommendations to adapt to a product, not a claim that every existing tool implements them.

This book contains unclassified guidance and synthetic examples approved for a public audience. [Publication and audiences](publication.md) describes that boundary and the GitHub Pages publishing workflow.

Start with the [CLI definition](glossary.md#cli) when the command-line vocabulary is unfamiliar.

## Further guidance

[TeamDman/Guides](https://github.com/TeamDman/Guides) contains existing tutorials and explanations. Follow a topic's source guidance and verify its applicability to the version and platform in use.
