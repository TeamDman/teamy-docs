# Generate offline sound effects

[Earshot](https://github.com/TeamDman/earshot) is a Python sound-effect generator. The inspected [upstream source revision](https://github.com/TeamDman/earshot/tree/591fa3e028032e6dce56620a20e932e35667e8d8) contains a code-backed bank of 252 sounds; the reviewed offline bank does not require model downloads. The [project metadata](https://github.com/TeamDman/earshot/blob/591fa3e028032e6dce56620a20e932e35667e8d8/pyproject.toml) specifies Python 3.10 or later, and the [audio implementation](https://github.com/TeamDman/earshot/blob/591fa3e028032e6dce56620a20e932e35667e8d8/earshot/audio.py) uses FFmpeg. Project code is MIT licensed; review reference-audio and generated-asset rights separately.

## Local Podman qualification

A separate local fork commit `3f373ada529c9685f19b43516db5a1c251c3c2f6`, not yet pushed, adds an offline Podman sound-bank renderer and its operation guide. Its synthetic qualification listed all 252 sounds and rendered a 0.094-second stereo 48 kHz 16-bit PCM click. The run used a non-root, read-only, network-disabled, resource-limited container; a Windows output mount and overwrite guard passed. No host Python or FFmpeg installation and no audio playback were required. This is a specific local test, not a general guarantee for all sounds or hosts; the local container guide is not yet available in the public fork.

The test excludes custom recipes, the MCP server, model-based analysis/forge and Gemini. The [MCP server](https://github.com/TeamDman/earshot/blob/591fa3e028032e6dce56620a20e932e35667e8d8/earshot/mcp_server.py) accepts accessible filesystem paths, and recipes can execute Python. The [configuration](https://github.com/TeamDman/earshot/blob/591fa3e028032e6dce56620a20e932e35667e8d8/earshot/config.py) and [forge implementation](https://github.com/TeamDman/earshot/blob/591fa3e028032e6dce56620a20e932e35667e8d8/earshot/forge/__init__.py) describe additional model and optional remote-service paths. Dependencies in upstream metadata are not a reproducible locked environment.

For a future build pipeline, prefer a pinned, unprivileged offline render worker with narrow input/output mounts, no network, credentials, Docker socket or device access, and explicit time and resource limits. Review generated assets, then ship the selected WAV files with the consuming application instead of embedding the generator in a privileged daemon. This is a deployment recommendation, not proof that every Earshot mode is safe inside a container.
